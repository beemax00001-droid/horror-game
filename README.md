# سامانه حرفه‌ای ختم قرآن

نسخه Static + Supabase این پروژه برای GitHub Pages و ویرایش با Acode ساخته شده است. هیچ Node.js یا build step لازم نیست.

## امکانات

- ۳۰ جزء قرآن با وضعیت آزاد / در حال مطالعه / تکمیل‌شده
- حداکثر ۳۲ شرکت‌کننده در هر ختم
- چند ختم مستقل و نگهداری آرشیو
- نقش مدیر و شرکت‌کننده
- احراز هویت Supabase Auth
- ورود شرکت‌کننده با Anonymous Auth و نام نمایشی
- حساب مدیر با رمز عبور Supabase Auth
- رزرو اتمیک جزء با PostgreSQL RPC و جلوگیری از انتخاب همزمان
- Supabase Realtime برای همگام‌سازی وضعیت اجزا، اعضا و ختم
- مطالعه جزء صفحه‌به‌صفحه با متن عثمانی
- ذخیره آخرین صفحه مطالعه
- اندازه متن قرآن
- صوت آیه‌به‌آیه با Al Quran Cloud CDN
- Dark Mode
- Activity Log و اعلان داخلی
- داشبورد و آمار مدیر
- آزادسازی جزء توسط مدیر
- آزادسازی همه اجزای غیرتکمیل‌شده
- گزارش ختم
- آرشیو ختم‌های مدیر
- اشتراک‌گذاری کد ختم با Web Share API
- QR Code برای ورود
- طراحی Mobile First و RTL
- GitHub Pages friendly با Hash Routing

## مرحله ۱ — ساخت Supabase

1. در Supabase یک Project رایگان بسازید.
2. وارد **SQL Editor** شوید.
3. تمام محتوای `supabase-schema.sql` را یکجا اجرا کنید.
4. در **Authentication → Providers**، گزینه **Anonymous Sign-Ins** را فعال کنید.
5. برای حساب‌های مدیر این نسخه Static، در تنظیمات Auth گزینه تأیید ایمیل را غیرفعال کنید. حساب مدیر با یک ایمیل داخلی ساختگی مانند `admin_abc123@khatm.app` ساخته می‌شود و ایمیل واقعی کاربر ذخیره یا لازم نیست.
6. در **Settings / API Keys**، Project URL و Publishable Key (یا کلید anon در پروژه‌های قدیمی) را بردارید.

> هرگز Secret/Service Role Key را داخل `config.js` قرار ندهید. کلید مرورگر باید فقط Publishable/Anon باشد و امنیت واقعی با RLS و RPCها اعمال می‌شود.

## مرحله ۲ — تنظیم config.js

فایل `config.js` را باز کنید:

```js
window.KHATM_CONFIG = {
  SUPABASE_URL: "https://YOUR-PROJECT.supabase.co",
  SUPABASE_KEY: "YOUR_SUPABASE_PUBLISHABLE_KEY",
  ...
};
```

دو مقدار را با اطلاعات پروژه خودتان جایگزین کنید.

هیچ مقدار دیگری لازم نیست تغییر کند.

## مرحله ۳ — اجرای محلی در Acode

چون پروژه build ندارد، می‌توانید فایل‌ها را در Acode نگه‌داری کنید.

برای تست ساده می‌توانید `index.html` را باز کنید؛ با این حال برای API/Realtime بهتر است سایت را روی GitHub Pages یا یک static server اجرا کنید.

## مرحله ۴ — GitHub Pages

کل پوشه پروژه را داخل Repository قرار دهید:

```text
index.html
config.js
supabase-schema.sql
README.md
css/...
js/...
```

سپس:

**GitHub → Settings → Pages → Deploy from branch → main / root**

پس از انتشار، آدرس GitHub Pages را باز کنید.

به دلیل استفاده از Hash Routing، مسیرهای برنامه به 404های رایج GitHub Pages دچار نمی‌شوند.

## نحوه ساخت ختم

1. «ایجاد ختم جدید»
2. نام ختم
3. نام مدیر
4. رمز مدیر، حداقل ۶ کاراکتر
5. سیستم یک کد ۶ رقمی/حرفی مثل `ABC123` می‌سازد.
6. مدیر وارد داشبورد می‌شود.
7. کد را با کپی، Share یا QR در اختیار اعضا قرار می‌دهد.

## ورود شرکت‌کننده

1. «ورود به ختم»
2. کد ۶ کاراکتری
3. نام
4. سیستم Anonymous Auth را برای دستگاه کاربر فعال می‌کند.
5. عضویت در دیتابیس ثبت می‌شود.
6. ظرفیت هر ختم ۳۲ نفر است.

## رزرو همزمان جزء

رزرو جزء با تابع PostgreSQL `claim_juz` انجام می‌شود.

تابع، ردیف همان جزء را با قفل تراکنشی (`FOR UPDATE`) می‌خواند و فقط اولین درخواست معتبر را می‌پذیرد. بنابراین دو گوشی نمی‌توانند یک جزء آزاد را به‌صورت موفق همزمان تصاحب کنند.

## Realtime

Realtime روی این جدول‌ها فعال شده است:

- `juz_assignments`
- `participants`
- `khatms`
- `notifications`

وقتی وضعیت جزء تغییر کند، کلاینت‌های متصل تغییر را دریافت و داشبورد را دوباره همگام می‌کنند.

## قرآن و صوت

متن قرآن از Al Quran Cloud API دریافت می‌شود.

هر جزء دریافت و بر اساس شماره صفحه گروه‌بندی می‌شود. صوت آیات از CDN رسمی/عمومی Al Quran Cloud به‌صورت داینامیک ساخته می‌شود.

اگر API قرآن در دسترس نباشد، پیام خطای فارسی نمایش داده می‌شود.

## امنیت

### چه چیزی در مرورگر است؟

- Project URL
- Publishable/Anon Key

این موارد برای اپلیکیشن‌های مرورگری قابل انتشار هستند.

### چه چیزی هرگز در مرورگر نیست؟

- service_role / secret key
- JWT secret
- رمز دیتابیس

### کنترل دسترسی

- RLS روی تمام جداول اصلی فعال است.
- عملیات حساس مانند claim/complete/release از RPCهای PostgreSQL استفاده می‌کنند.
- claim اتمیک است.
- مدیر فقط ختم‌هایی را که خودش مدیر آن‌هاست می‌تواند مدیریت کند.
- شرکت‌کننده فقط از مسیر RPC می‌تواند جزء خود را claim/complete کند.

## نکته مهم درباره احراز هویت مدیر

برای اینکه فرم مدیر فقط «نام + رمز» داشته باشد، حساب Auth مدیر با یک ایمیل داخلی بر اساس کد ختم ساخته می‌شود. کاربر آن ایمیل را لازم نیست بداند؛ ورود با کد ختم + رمز انجام می‌شود و برنامه از RPC `get_admin_login` ایمیل داخلی را پیدا می‌کند.

اگر Confirm Email فعال باشد، ساخت حساب مدیر ممکن است بدون Session تمام شود. برای این نسخه Static، Confirm Email را برای این حساب‌ها خاموش کنید.

## آرشیو چند ختم

ساختن ختم جدید، رکورد ختم قبلی را حذف نمی‌کند.

هر ختم دارای `id` مستقل است و اجزا، اعضا، فعالیت‌ها و گزارش‌ها با `khatm_id` به آن متصل هستند.

مدیر در پنل، بخش «آرشیو» را می‌بیند و ختم‌های قبلی خودش را مشاهده می‌کند.

## محدودیت معماری Static

این پروژه عمداً بدون Node.js و Backend اختصاصی ساخته شده است. Supabase Backend-as-a-Service نقش Backend را انجام می‌دهد.

برای محصول بسیار بزرگ‌تر می‌توان در آینده:

- Supabase Edge Functions
- ایمیل واقعی برای Auth
- نقش‌های سازمانی
- لاگ امنیتی پیشرفته
- Cache/CDN قرآن
- PWA کامل
- Push Notification واقعی

را اضافه کرد، بدون اینکه مدل داده اصلی عوض شود.

## عیب‌یابی

### «تنظیمات اتصال کامل نشده است»
`config.js` را بررسی کنید.

### «ثبت‌نام مدیر نیاز به تأیید ایمیل دارد»
Confirm Email را در Auth غیرفعال کنید.

### «ظرفیت تکمیل شده»
هر ختم حداکثر ۳۲ participant دارد.

### «ارتباط با سرور برقرار نشد»
اتصال اینترنت، Project URL، Publishable Key و RLS/SQL را بررسی کنید.

### Realtime کار نمی‌کند
مطمئن شوید SQL کامل اجرا شده و جدول‌های realtime در publication قرار گرفته‌اند. سپس صفحه را یک‌بار refresh کنید.

## تست پیشنهادی

بعد از راه‌اندازی:

1. یک ختم بسازید.
2. کد را در گوشی دوم باز کنید.
3. دو نام مختلف وارد کنید.
4. در گوشی اول جزء ۵ را انتخاب کنید.
5. در گوشی دوم بدون Refresh وضعیت جزء ۵ را بررسی کنید.
6. در هر دو گوشی روی اجزای مختلف کار کنید.
7. یک جزء را تکمیل کنید و Realtime را بررسی کنید.
8. در پنل مدیر یک جزء reading را آزاد کنید.
9. یک ختم دوم بسازید و مطمئن شوید ختم اول همچنان در آرشیو باقی مانده است.

## مجوز و منابع

این پروژه کد اپلیکیشن را ارائه می‌کند و برای متن/صوت قرآن از سرویس Al Quran Cloud استفاده می‌کند. شرایط و محدودیت‌های سرویس خارجی را قبل از انتشار عمومی بررسی کنید.
